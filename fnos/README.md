# FlClash 飞牛原生集成 0.2.1（待实机验收）

面向 fnOS **1.2.0505 / Intel、AMD x86_64**。这是独立的 NAS 后台与中文 Web 配置页，复用本仓库 Go 核心和地理数据，不需要运行 Flutter、Docker 或 Node.js。

**安装包构建与实机兼容性验收是两件事。0.2.1 已完成开发机回归和固定核心构建，尚未完成修复包升级安装及真实流量复验，不应部署到无人值守的重要 NAS。详见 [0.2.1 测试记录](TESTING-0.2.1.md)。**

## 安装与首次使用

1. 校验 `.fpk.sha256`，在飞牛应用中心选择“手动安装”，上传 `.fpk`。
2. 首次安装只启动管理服务。使用 NAS 管理员打开桌面上的 FlClash 图标。
3. 在“配置 → 添加配置”选择订阅、本地文件或粘贴 YAML，默认“导入并使用”，也可“仅导入”。导入成功不等于使用成功；核心拒绝时档案保留，原有效运行配置不被替换。
4. 在“概览”选择实际承载主要流量的主要策略组，再选节点与规则／全局／直连模式。全局模式检测 GLOBAL，规则模式使用保存的主要策略组；自动策略不能手动覆盖。
5. 在“网络”明确选择“仅 IPv4”或“IPv4 + IPv6 双栈”，勾选范围确认并保存检测。处理所有阻塞项后回到概览开启代理。配置导入不会自动开启接管。

## 0.2.x 控制台操作

- 顶栏与导航固定，右侧内容独立滚动；切页保留各自滚动位置。窄于 760px 的窗口使用顶部页面菜单。
- 配置列表的“更多 → 编辑”可改名、改更新间隔、替换订阅地址。原地址不反显，留空保留；替换下载或使用失败不覆盖旧订阅。
- 节点页只展开当前策略组，可搜索、按原顺序或延迟排序。每次先呈现 80 项，再点“显示更多”。保留订阅分组、成员、顺序及说明性名称。
- “检测当前列表”测试搜索后的所有成员，最多两项并行。“停止排队”保留进行中的两项及已完成结果，不再发出排队请求；结果显示检测时间，不自动换节点。
- 日志支持搜索、暂停自动刷新与跟随最新。阅读历史记录时不会强制滚到底部。服务重启后内存日志清空。
- 管理服务连接、核心配置就绪、透明代理接管分开显示。断线时保留上次快照并显示过期警告，不伪装为核心停止或零流量。
- 设置按字段分别保存；长操作期间状态快照仍可读取。互斥写入在后台串行执行，忙碌时返回稳定分类 `operation_busy`，不会重复启动核心。

所有接入对象共享规则与节点。保留的管理和网络参数不会受订阅覆盖。集合仅支持 HTTP/内联，不支持导入配置引用任意本地文件。HTTP 订阅可能泄露凭据，优先使用 HTTPS。后台下载订阅可访问 NAS 可达的 HTTP/HTTPS 地址，因此接口仅向管理员开放。

Web 只使用飞牛统一网关 `/app/flclash`，不额外开 LAN 管理端口。网关 Socket 仅 root 可连接，Web 子进程另以 `flclash` 用户运行，并校验 `X-Trim-Userid`、`X-Trim-Isadmin`、`X-Trim-Username`。若目标版本网关并非 root 身份，当前会拒绝连接；应实机确认身份后做最小授权，**不要改为所有用户可写或跳过管理员校验**。

写入接口还要求管理员专属防跨站令牌，由同源页面通过不缓存的 `/api/session` 获取；令牌绑定管理员身份，并随 Web 进程重启失效。校验不依赖反向代理保留外部 Host，拒绝已标记为跨源的浏览器请求，不开放 CORS。

## 网络接入与限制

| 对象 | 连接方式与验证要求 |
| --- | --- |
| NAS 自带应用 / Docker 镜像下载 | 宿主机 TUN 接管；分别验证 IPv4/IPv6 和 DNS |
| Docker host | 共用宿主机网络；检查宿主机出站和入站服务 |
| Docker bridge | 流量需经过 NAS 转发；检查 Docker 防火墙、互访及已发布端口 |
| 飞牛虚拟机 / OVS | 在虚拟机中查看默认路由；桥接存在不表示经过 NAS 路由 |
| macvlan / ipvlan / 网卡直通 | 不宣称自动支持；改为可经 NAS 路由的连接后再测 |

网关客户端步骤：

1. 记录原 IPv4/IPv6 网关、DNS、网卡设置；确保 NAS 管理地址可直连访问。
2. 在页面登记明确的私有客户端 CIDR。IPv4 提供 NAT，IPv6 私有 ULA 可提供 NAT66；IPv6 全局地址依赖已有可用路由。
3. 在客户端手动调整默认网关，IPv4 与 IPv6 分别配置。不会自动修改家庭路由器、虚拟机配置或 OVS。
4. 验证客户端到 NAS 互通，再测两种 IP 协议的 TCP、UDP 与 DNS。
5. 不要把“检测通过”当成“流量已验证”。本版覆盖列表保守显示“待接入”，须按验收表记录真实结果。

TUN 使用 `mixed` 栈、自动路由及自动重定向；独立路由表 `31001`、规则段 `31000–31020`、回退规则 `41050`、标记 `0x3f01/0x3f02`。DNS 使用 `redir-host` 和系统解析器，不修改 `/etc/resolv.conf`，不开放独立 DNS 监听端口。局域网、接口直连网段、组播及链路本地地址排除接管，Docker `127.0.0.11` 内部 DNS 继续由 Docker 处理。

双栈模式要求两个地址族均有默认出口。仅 IPv4 模式只要求 IPv4 出口和公共安全条件通过；缺少 IPv6 出口显示“不参与接管”，不阻塞本次开启。不会根据检测结果悄悄切换模式，旧设置缺少 `networkMode` 时按双栈解释。

**仅代理 IPv4；IPv6 可能直接连接，不提供 IPv6 防泄漏保证。** 仅 IPv4 模式关闭核心 IPv6、清空 IPv6 TUN 地址、移除 IPv6 DNS 接管，并让核心 DNS 的 AAAA 查询返回空结果；不禁用 NAS 系统 IPv6，不修改其 IPv6 网关、RA 或防火墙配置。局域网 DNS、系统解析器回环、Docker 防火墙顺序仍需实测。没有进入核心 DNS 的请求不受其 AAAA 行为约束。

仅 IPv4 模式拒绝 IPv6 网关客户端网段。切换网络模式必须先关闭接管；有保留转发时，先恢复相关客户端原网关，再执行本应用网络恢复。恢复按归属日志里的实际地址族执行，旧日志按双栈解释，不按当前页面选项猜测。

本应用不清空任何全局路由表、防火墙或 Docker 链。nftables 不可用时拒绝开启，不回退到可能不可追踪的 iptables 接管。其他 VPN、策略路由及 NAS 防火墙可能冲突，检测失败时保持直连并讨论适配。

登记网关客户端后，另外使用 `iptables` / `ip6tables` 兼容接口插入带 `flclash-gateway` 标记的窄范围 FORWARD 规则，只允许指定客户端网段到出口或 TUN 的流量，以及对应的已建立连接返回；不会修改 FORWARD 默认策略。删除时按持久日志中的完整规则匹配。缺少兼容接口时不宣称网关转发可用。这与核心透明接管禁止 iptables 回退是不同机制。

## 关闭、降级与恢复

- **关闭代理**：停止 TUN 接管，保留已登记网关客户端的普通转发。
- **节点故障**：成功开启后每 20 秒检测实际出口组，连续三次失败撤销 TUN；连续两次成功重新开启。规则模式存在多个独立出口时，单个检测组不能代表所有节点；选择主要出口并查看核心日志。
- **首次开启失败**：保存关闭状态和阻塞原因，不进入直连降级和自动恢复循环。修正条件后由用户重新开启。
- **核心退出 / IPC 断开**：撤销本应用 TUN 路由、防火墙表并显示直连降级。保留用户模式、节点选择和档案，恢复时重新应用。
- **监督进程意外退出**：核心通过父进程死亡信号退出；独立恢复守卫读取持久变更日志，撤销 TUN。该行为须在 Linux 实测 SIGKILL 与重启。
- **停用整个应用、卸载、关闭 NAS**：先将网关客户端恢复原网关，否则 NAS 停止转发后它们可能断网。NAS 关机时无法弹出本应用交互向导，请提前执行此步骤。

页面“网络 → 恢复网络变更”会关闭代理，并在确认客户端网关已恢复后，撤销本应用转发设置。sysctl 只在同一次开机、当前值仍等于本应用设置值时恢复原值，避免覆盖后来其他服务的修改。错误配置应用失败会重载原配置；回滚失败则停止核心、撤销接管并显示错误。

如果管理页面不可用：先通过原管理 IP 进入 NAS，或使用本地控制台 / 已启用的 SSH。先恢复虚拟机网关，停止应用；若监督服务已退出，可使用：

```sh
sudo /var/apps/flclash/target/bin/FlClashFnos recover \
  /var/apps/flclash/target \
  /实际的应用共享目录/flclash/data/private \
  /run/flclash
```

请用安装时实际数据目录替换示例，不要复制猜测的磁盘路径。`recover` 拒绝与正在运行的监督服务同时操作。不要手动 `nft flush ruleset`、清空 Docker 链或删除系统路由。

## 数据、升级与卸载

资源声明 `flclash/data`，私有状态在其 `private` 子目录，root 所有、权限 `0700`；设置和订阅文件 `0600`。其中包含订阅凭据，备份应按敏感数据保护。Web 用户不能直接读取该目录。

- `settings.json`：设置、档案、订阅、节点选择，原子替换。
- `last-good.yaml`：最近应用成功的配置。
- `core/`：核心工作目录、运行配置、集合缓存和地理数据。
- `network-journal.json`：接管归属、实际地址族、开机标识、sysctl 原值。
- `startup.log`：本次启动错误；页面日志为内存中最近 500 条，重启后清空。

升级保留共享目录。卸载默认保留私有配置，重装到同一存储空间使用；只有明确选择“永久清除配置”才删除该私有子目录中的内容。共享目录保留行为与重装恢复仍需在目标 fnOS 验证。

## 构建

要求 Go **1.26.4**、Git、官方 **fnpack 1.2.3**，可在 Windows 或 Linux 交叉构建。必须使用现有仓库与其固定 mihomo 子模块，不需要下载另一份 FlClash。

```powershell
cd E:\Workspace\Other\FlClash\fnos
..\build\fnos\tools\go\bin\go.exe test ./...
..\build\fnos\tools\go\bin\go.exe run ./cmd/build-fpk `
  -root .. `
  -go ..\build\fnos\tools\go\bin\go.exe `
  -fnpack ..\build\fnos\tools\fnpack.exe
```

Linux 已配置 Go 和 fnpack 的环境：

```sh
cd fnos
go test ./...
go run ./cmd/build-fpk -root .. -go go -fnpack fnpack
```

构建入口读取仓库 `options.dart` 的现有核心默认参数与 `build_config.yaml` 覆盖项，并校验子模块提交和干净状态。使用 `CGO_ENABLED=0`、Linux AMD64 v1，不依赖目标机器 glibc。

仅飞牛构建使用两个严格匹配的 Go overlay：将核心自动重定向表名从 `mihomo` 隔离为 `flclash_tun`；将 nftables 初始化失败后的 iptables 回退改为报错。不会修改子模块源码或其他平台构建。核心升级导致匹配改变时构建直接失败，要求复审。覆盖源、overlay JSON 和 staging 保留在 `build/fnos/package-*` 便于审计。

输出在 `build/fnos/`：`.fpk`、`.fpk.sha256`、`build-info.json`。包中复用既有 FlClash 图标、GEOIP/GEOSITE/ASN 数据。依赖版本固定，但 fnpack 可能写入打包时间，因此不承诺每次 FPK 字节完全一致。

Windows 版 fnpack 输出没有保留 Linux 可执行权限。构建入口在官方打包后校验其 `manifest.checksum` 确为 `app.tgz` 的 MD5，再统一 tar 中 root 所有权、目录及脚本/二进制 `0755`、普通文件 `0644`，同步更新内部 MD5，最后生成外部 SHA256。若官方校验约定变化会拒绝处理，不生成未经校验的安装包。
