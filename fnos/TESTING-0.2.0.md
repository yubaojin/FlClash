# FlClash 飞牛 0.2.0 测试记录

记录日期：2026-09-08。目标：fnOS 1.2.0505 / Intel、AMD x86_64。

## 交付结论

**代码与 FPK 已生成，开发机自动化回归通过；飞牛 0.2.0 升级、真实订阅与透明代理实机验收尚未完成。** 不得将模拟页面的“代理已开启”“出口条件通过”解释为 NAS 流量已被接管。

- 安装包：仓库 `build/fnos/FlClash-0.2.0-fnOS-x86_64.fpk`。
- SHA256 以同目录的 `.fpk.sha256` 为准。说明与截图也随包交付；报告不嵌入所在安装包自身的哈希，避免校验循环。
- 构建：Go 1.26.4，官方 fnpack 1.2.3，Linux AMD64 v1，固定 mihomo 提交 `0f7f05adff5e2c49775a112dcfe05a6aa36fda0c`。
- `build-info.json` 的 `hardwareAcceptance` 保持 `false`。
- 不修改 Flutter、Android 或 mihomo 子模块。升级保留原有数据目录，不自动删除测试配置。
- 本轮没有把真实订阅 URL、口令或节点凭据写入源码、测试样例、截图报告或 FPK。

## 复现、修复与回归

| 问题与复现方法 | 0.2.0 修复 | 验证范围 |
| --- | --- | --- |
| 旧页面打开长列表并滚动，顶栏和导航一起离开视野 | 外层禁止滚动，56px 顶栏和 176px 侧栏固定，右侧正文是唯一纵向滚动区，切页保留位置 | 浏览器长节点列表滚动、缩小窗口滚动、DOM 回归 |
| 同时展示多种配置输入，失败不清楚是保存还是应用 | 三来源弹窗，默认导入并使用；部分成功保留新档案与旧运行配置，错误留在弹窗 | 浏览器粘贴导入、部分成功自动化 |
| 保存某项设置可能携带并覆盖其他设置 | 后台指针字段 PATCH 语义；前端每个表单只提交自己负责的字段 | Go 与 DOM 回归 |
| 500 节点和多个组全部铺开，搜索和当前选择难找 | 单策略组、每批呈现 80 项、搜索、稳定延迟排序、检测时间、两项并发、停止排队 | 500 节点模拟浏览器与自动化 |
| 轮询重新创建控件，输入或操作被打断 | 稳定对象身份，保留草稿、焦点、搜索、检测结果；读取请求带过期门控 | DOM 回归 |
| 历史错误跨页残留，恢复后错误仍占页面 | 页面、表单与对象分区错误；区分读取错误和操作错误；成功短暂提示 | DOM 故障与恢复回归 |
| 管理连接、核心进程和代理接管混为一谈 | 分别返回配置就绪、接管状态、快照时间、真实操作阶段；断线显示状态过期 | 模拟断线与状态回归 |
| 缺少 IPv6 出口阻止 IPv4 使用 | 显式 IPv4 / 双栈模式，检测结果含地址族与阻塞属性；仅 IPv4 不要求 IPv6 出口 | Go 配置、检测、恢复命令测试 |
| 第一次开启前置失败仍持久化开启意图并反复恢复 | 成功开启后才保存开启；首次失败保持关闭与阻塞原因 | 两种原始 enabled 状态回归 |
| 冷启动回滚可能读取上次含 TUN 的运行文件 | 回滚将 TUN 状态限制为当前实际接管状态，不复活无归属接管 | Go 回归 |
| 两项测速同时读取状态偶尔互相误报忙碌 | 使用读写锁捕获核心快照，RPC 在锁外；后台限制两项并发 | 专项连续 10 轮 |
| 新会话保护遗漏状态响应中的 session，正常测速会被当作旧结果 | 状态与节点、测速响应统一携带 session 和 revision | 先复现失败，再通过状态→测速接口专项 10 轮及真实核心回环测试 |

仅 IPv4 生成配置关闭核心 IPv6、清空 IPv6 TUN 地址与 IPv6 DNS 接管。固定核心的 `dns/middleware.go` 中普通解析路径会对禁用 IPv6 的 AAAA 查询返回空结果，与 [DNS 规范](https://wiki.metacubex.one/config/dns/) 一致；[TUN 规范](https://wiki.metacubex.one/config/inbound/tun/) 用于核对地址族和接管配置。未进入核心 DNS 的流量不受此行为保证。系统 IPv6 保持原样，可能直连，不承诺 IPv6 防泄漏。

## 自动化实际结果

环境为 Windows 开发机，不是 Linux 网络命名空间或 NAS。

| 检查 | 结果 |
| --- | --- |
| `npm.cmd test` | 14 项前端测试通过；新增固定顶栏、固定导航和唯一正文滚动区约束 |
| 指定真实核心和实际 FPK 的 `go test -count=3 ./...` | 连续三轮通过 |
| 最终 `go test -json -count=1 ./...` | 52 个通过事件（含子测试），无失败或跳过 |
| 当前会话测速与并发/迟到结果专项 | 连续 10 轮通过 |
| `TestRealCoreProtocolAndRollback` | 真实 Windows 核心三轮通过，包含配置应用、语义错误回退、节点协议及后台测速接口 |
| Windows / Linux AMD64 的 `go vet ./...` | 均通过；Linux 为静态检查，不代表 Linux 上执行了测试 |
| `node --check`：app.js、model.js | 通过 |
| 实际 FPK 检查 | 内部校验、权限、最低版本、两个 Linux AMD64 ELF 通过 |

真实核心测速目标是开发机的临时回环 HTTP 服务，只验证 IPC 和接口契约；TUN 始终关闭。该测试不是用户真实订阅节点测试，不作为代理流量验收。

网络测试通过注入命令执行器验证：缺 IPv6 时两模式判定差异、IPv4 不写 IPv6 转发/RA、拒绝 IPv6 网关网段、恢复读取归属日志而非当前设置、兼容旧双栈日志、未授权规则不被全局清空。它们不能证明目标 NAS 上 nftables / Docker / OVS 的实际组合已经兼容。
