## 可在开发机执行

```sh
cd fnos
go test ./...
go vet ./...
GOOS=linux GOARCH=amd64 CGO_ENABLED=0 go build ./cmd/flclash-fnos
node --check internal/service/web/app.js
node --test tests/web.test.mjs
```

原核心使用 `CGO_ENABLED=0 go test .` 和 `go vet .`，不收集覆盖率。未修改 Flutter/Android，所以飞牛验证不依赖 Flutter 构建。

2026-09-06 开发机验证：Windows 上的配置保留参数、订阅失败保留、IPC 乱序/断连/超时/超大帧、管理员/跨站请求限制、有界日志、网络归属恢复和错误配置回滚测试已通过。另以真实 Windows FlClashCore 和命名管道验证初始化、配置应用、读取策略组、语义错误回滚、节点选择和退出。实际 FPK 检查包括内部 MD5、文件权限、最低系统版本和两个 Linux AMD64 ELF 二进制。以上不替代下列 Linux/飞牛测试。

指定真实核心和实际安装包可额外运行集成测试：


真实核心测试只应用 TUN 关闭且没有代理监听端口的测试配置，不接管开发机网络。

## Linux 故障注入（仅隔离测试机）

- [ ] 创建包用户后，以 root 启动监督服务；确认 Web 实际 UID 非 0。
- [ ] 重复启停与并发重启，任一时刻最多一个核心进程。
- [ ] 伪造本地普通用户连接、普通 NAS 用户访问被拒绝；管理员成功。
- [ ] 无鉴权头、错误管理员头、跨站 POST、未知接口、超大请求拒绝。
- [ ] 核心 SIGKILL / IPC 断开后，TUN、专属规则与表撤销，原系统规则不变。
- [ ] 监督进程 SIGKILL 后核心退出、守卫恢复；重复恢复幂等。
- [ ] 启动前占用专有名称/规则编号时拒绝接管。
- [ ] sysctl 外部改动不被恢复覆盖；重启后不重放旧开机原值。
- [x] 有效配置后应用语义错误 YAML，原配置和档案继续有效（真实 Linux 核心，TUN 关闭）。
- [ ] 订阅 HTTP 错误、超时、格式错误、重定向降级，不替换旧档案。
- [ ] 节点持续失败后直连降级，恢复后原选择与原模式不丢失。
